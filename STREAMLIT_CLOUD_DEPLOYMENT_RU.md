# Публикация Uncharted на Streamlit Community Cloud

Эта инструкция подготовлена по официальной документации Streamlit, проверенной 18 октября 2026 года. Community Cloud берёт код из GitHub и запускает выбранный файл приложения. В этом проекте точка входа — `app.py`, а зависимости указаны в корневом `requirements.txt`.

Официальные инструкции: [Deploy your app](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy), [структура файлов](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/file-organization), [зависимости](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies), [доступ и публикация приложения](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app).

## Что уже подготовлено

- В проекте есть `app.py`, закреплённый `requirements.txt`, переводческие файлы, тесты, бенчмарк и демонстрационный CSV.
- Пути к переводам рассчитываются относительно `localization.py`; абсолютных путей к компьютеру разработчика в коде приложения не найдено.
- `.gitignore` исключает виртуальные окружения, настройки PyCharm/VS Code, кеши, локальные секреты, журналы и временные файлы.
- Приложение не сохраняет загруженные CSV в файлы и не вызывает внешние сервисы. Оно анализирует загруженный файл в активной сессии Streamlit.
- Удалённый адрес `origin` уже задан, но в локальном репозитории пока нет первого коммита. Публичность GitHub-репозитория из текущей среды подтвердить не удалось.
- Коммит, отправка на GitHub и публикация приложения не выполнялись.

## 1. Проверь GitHub-репозиторий

Открой на GitHub репозиторий, указанный командой `git remote -v`. Проверь, что это нужный репозиторий и что в нём нет чужих или конфиденциальных файлов. Чтобы публичная ссылка была доступна всем, репозиторий можно сделать публичным в **Settings → General → Danger Zone → Change repository visibility → Make public**. Перед этим проверь содержимое репозитория: публичными станут весь его код и история.

В PyCharm открой вкладку **Terminal** (PowerShell) и перейди в папку проекта, если терминал открыт не там:

```powershell
cd C:\Users\asus\PycharmProjects\chart-auditor
git status --short --branch
git remote -v
git ls-remote --heads origin
```

Сейчас ожидается локальная ветка `master` без коммитов. Если `git ls-remote --heads origin` выводит ветви, значит на GitHub уже есть история. Не используй `--force`: остановись и сначала согласуй историю локального и удалённого репозиториев. Если команда завершается ошибкой сети или доступа, сначала проверь подключение и права GitHub.

## 2. Проверь файлы, которые попадут в GitHub

Нужно включить исходный код, переводы, документацию, тесты, бенчмарк и небольшой демонстрационный CSV. `.gitignore`, `README.md`, `README_RU.md`, `STREAMLIT_CLOUD_DEPLOYMENT_RU.md`, `app.py`, `auditor.py`, `data_loader.py`, `export_utils.py`, `localization.py`, `requirements.txt`, папки `locales/`, `examples/`, `tests/` и `evaluation/` нужны проекту.

Не добавляй `.venv/`, `venv/`, `env/`, `.idea/`, `.vscode/`, `__pycache__/`, кеши, файлы `.env`, `.streamlit/secrets.toml`, логи, временные файлы, персональные данные и случайные локальные артефакты. Текущий список `.gitignore` исключает эти категории.

Добавь только нужные пути и проверь staged-файлы до коммита:

```powershell
git add .gitignore README.md README_RU.md STREAMLIT_CLOUD_DEPLOYMENT_RU.md app.py auditor.py data_loader.py export_utils.py localization.py requirements.txt locales examples tests evaluation
git status --short
git diff --cached --name-only
git diff --cached --stat
```

Если в списке появились лишние файлы, остановись и убери их из индекса командой `git restore --staged <путь-к-файлу>`. Эта команда снимает файл только с подготовки к коммиту и не удаляет его с диска.

## 3. Первый коммит и отправка на GitHub

Выполняй эти команды только после проверки staged-списка. Я их не запускал:

```powershell
git commit -m "Prepare Uncharted for Streamlit Community Cloud"
git push -u origin master
```

Поскольку текущая локальная ветка называется `master`, она указана в команде. Если проверка GitHub показала существующие удалённые коммиты, не выполняй этот push до согласования историй. Не применяй `git push --force`.

После отправки обнови страницу GitHub и проверь, что на ветке `master` видны `app.py`, `requirements.txt`, `locales/`, `examples/uncharted_demo.csv`, тесты и документация, а `.venv/` и `.idea/` отсутствуют.

## 4. Создай приложение Streamlit Community Cloud

1. Открой [share.streamlit.io](https://share.streamlit.io/) и войди через GitHub. Разреши доступ к нужному аккаунту или организации, где расположен репозиторий.
2. В рабочей области этого владельца нажми **Create app** и выбери **Yup, I have an app**.
3. Укажи GitHub-репозиторий `chart-auditor`, ветку `master` и путь к основному файлу `app.py`. Если список не показывает значения, введи их вручную.
4. В **Advanced settings** выбери Python **3.12**. По актуальной документации Streamlit Community Cloud сейчас использует Python 3.12 по умолчанию. `requirements.txt` уже закрепляет версии Streamlit, Pandas и Plotly.
5. Нажми **Deploy** и дождись установки зависимостей и запуска приложения. Платформе потребуется доступ к репозиторию.

Приложению не нужны API-ключи, секреты, база данных или Linux-пакеты; поле Secrets оставь пустым.

## 5. Проверь публичную ссылку

После успешного запуска Streamlit покажет ссылку вида `https://…streamlit.app`. Реальный адрес можно указывать в `README.md` только после того, как он появится.

Открой ссылку в приватном окне браузера или попроси другого человека проверить доступ без входа в твой аккаунт. Убедись, что:

- страница загружается и начинается на русском;
- переключатель меняет язык на английский и обратно;
- `examples/uncharted_demo.csv` загружается, таблица и метрики отображаются;
- строятся все пять типов графиков, результаты аудита и сравнение;
- скачиваются CSV, JSON и оба HTML-графика;
- публичность приложения настроена в его **Settings / Sharing**. У публичного GitHub-репозитория приложение обычно открыто по ссылке, но проверь настройку **Who can view this app**.

Не загружай в публичное демо реальные конфиденциальные, персональные или регулируемые данные. Код приложения не сохраняет CSV в постоянные файлы и не передаёт его сторонним сервисам, но это не обещание абсолютной конфиденциальности облачной платформы. Публичное демо следует проверять на демонстрационных данных.

## 6. Как обновлять опубликованное приложение

После будущих изменений локально запусти тесты, проверь список изменений, затем подготовь и отправь нужный коммит. Community Cloud отслеживает исходный GitHub-репозиторий: отправленные изменения обычно обновляют приложение автоматически; изменение зависимостей вызывает их повторную установку.

```powershell
python -m unittest discover -s tests -v
git status --short
git add <изменённые-файлы>
git diff --cached --stat
git commit -m "Describe the change"
git push
```

Не добавляй локальные файлы проекта целиком, не проверив staged-список.

## 7. Где смотреть ошибки запуска

Открой опубликованное приложение, нажми **Manage app** в нижнем правом углу и перейди к Cloud logs. Журналы — основной способ понять, почему установка зависимостей или запуск завершились ошибкой. Проверь начало трассировки и первое сообщение об ошибке, сверяй имя отсутствующей библиотеки с `requirements.txt`, исправь проект локально, запусти тесты, затем отправь исправление в GitHub.

Если изменился Python runtime, учти: после публикации версию Python нельзя просто переключить в настройках существующего приложения — потребуется удалить приложение и развернуть его заново. Сначала проверь актуальное описание в официальном разделе [Upgrade Python](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app/upgrade-python).

## Известные ограничения публикации

- Публикация, ссылка и доступ через браузер ещё не проверены: для этого требуются коммит и push, которые владелец репозитория должен выполнить самостоятельно.
- Приложение зависит от ресурсов и правил Streamlit Community Cloud; платформа может менять ограничения.
- Аудит использует явные правила и эвристические пороги, а не оценку намерений автора.
- Загрузки не записываются приложением в постоянное хранилище, но публичное облачное размещение не подходит для секретных или регулируемых данных.
